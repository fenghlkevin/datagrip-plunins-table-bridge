# 断点与主键同步（0.3.0-alpha）

范围为 MySQL、PostgreSQL、Oracle；不新增 SQL Server 功能。Oracle 实库不可用，相关实现不能视作已验收。

## 操作

对象页可以勾选“启用断点与恢复”；目标已存在策略新增“增量：按主键新增/更新”和“同步：按主键新增/更新/删除”。同步保留目标结构，要求来源和目标完整主键一致，MySQL 目标必须 InnoDB。

“恢复任务…”加载 IDE system/tablebridge/jobs 中的任务 XML，要求来源、目标连接和模式匹配。计划保存执行定义与连接标识的摘要，不保存密码、记录数据或主键游标。执行阶段保留该计划的 UUID，不重新创建计划。配置 v6 保存恢复选项及重载签名，兼容 v1–v5。

暂存和检查点在目标模式中，以随机任务 UUID 派生 tb_s_/tb_j_ 表名。需要建表权限和额外空间。恢复任务保留这些对象直到用户点击“清理当前任务暂存”；清理核对任务所有权和计划摘要，只删除该任务的内部表及本机恢复计划，保留目标业务对象。

## 保护与边界

- 来源使用独立 repeatable-read / Oracle serializable 事务；按完整主键进行 500 行 keyset 分页。
- 每页暂存与游标一同提交。恢复加载中的任务重新核对全来源摘要；来源改变时拒绝混合新旧快照。
- READY 暂存再次校验摘要，已确认 APPLIED 的任务不重放 DML。完成暂存后恢复使用已冻结快照。
- 全部目标 DML 和 APPLIED 标记在同一事务提交。内容校验失败回滚该批写入；结构与暂存创建的 DDL 不因此回滚。
- 增量按主键匹配，保留目标额外记录；镜像另行删除来源缺失主键。目标实际外键安排父表先写、子表先删；PostgreSQL 全部相关外键可延迟时在事务内延迟检查，其他循环在写入前拒绝。外部未选依赖由约束拒绝并回滚，未禁用约束或触发器。
- Oracle/MySQL 结构隐式提交结果不明时停止人工核查，不盲目重复 DDL。连接 SQLState 08、事务冲突 40001/40P01 等至多自动重试两次；取消、语法错误不重试。
- 原来的高速普通复制仍可用；断点模式多次摘要读取、暂存与检查点会增加耗时。
- APPEND 目标内容按原有记录摘要与暂存摘要之和校验；没有主键的表不能断点或自动同步。恢复 XML 不是数据库备份，不恢复已被 DROP 的旧表。
- 动态 SQL 和重载歧义要求手工定义及显式依赖；非延迟循环不自动关闭外键。Oracle 实库测试及验收按用户要求排除，未验收路径如已有 identity 表的追加仍保守限制。

## 0.3.4-alpha：只读同步差异预览

新建增量/镜像同步计划自动预览，可在确认页“同步差异”刷新。按完整复合主键比较，使用 RowDigest 的数值/NULL/二进制/日期等归一化规则，给出预计新增、更新、删除、保留数和最多 20 条主键/字段变化样例。来源和目标使用独立快照事务，只执行读取和会话配置，结束时回滚；不创建任务表。

每表每侧查询限制为 50,001 行，其中第 50,001 行用于拒绝超限；累计归一化内容限制 32 MiB。超限或取消不发布部分统计，允许用户重新确认后使用原有同步，无成功预览时不增加过期检查。LOB 单值依旧整体读取，内容上限不是 JVM 总内存上限。

成功预览仅在内存中保存摘要、字段类型和样例；执行前检查来源/目标摘要，暂存完成后再次检查目标和暂存摘要，差异停止 DML。已确认 APPLIED 的重试仍不重放写入。刷新重新取消执行确认。恢复 XML 不持久化预览或样例，重新打开恢复任务使用原有冻结快照，不提供刷新预览。

统计为估算：不同排序规则下的文本主键等价、目标精度/时区/JSON 文本语义和触发器可能与归一化比较不同。检查不锁定目标业务表，最终复查后的并发写入仍按现有数据库约束与内容校验处理，不保证预览到提交期间的数据冻结。Oracle 预览实现未做本次实库验收。
